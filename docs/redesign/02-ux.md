# 02 · 交互与信息架构

## 1. 三种节奏，三个表面

照片浏览器被用起来的节奏只有三种，界面必须各自给出最短路径：

| 节奏 | 用户在做的事 | 表面 | 最短路径 |
|---|---|---|---|
| **扫视**（scan） | 这一墙里有没有我要的 | 网格 | 滚轮 + 密度档 |
| **挑拣**（cull） | 这批里留下哪几张 | 网格 | 方向键 + 0–5 + ⌫ |
| **细看**（inspect） | 这一张到底怎么样 | 大图 | 空格进入，Esc 退出 |

导航栏（rail）不属于任何一种节奏，它是**换墙**的地方，所以它永远在、永远窄。

设计上的推论：**挑拣必须发生在网格里**。把 100 张照片一张张打开再关掉是最慢的路径，
所以键盘游标、选择集合、快速评分、快速删除全部长在网格上，而不是只长在大图里。

## 2. 能力边界（先说清楚不做什么，免得设计悬空）

这些不是取舍，是 nanoui 0.6.4 当前的硬边界；方案按边界设计，不按愿望设计。

| 边界 | 证据 | 设计应对 |
|---|---|---|
| **没有右键** | `Input` 只有 `down / pressed / released / click_count`，没有 button 字段；全框架没有 `rightMouse` | 每个图块右上角一枚 ⋯ chip（悬停/游标/选中时出现）；常用动作另有直接快捷键，菜单不是必经之路 |
| **滚动容器只垂直** | `Style.scroll` 注释：「children are clipped to the box and scroll vertically」 | 大图胶片条做成**窗口式**（当前居中的 15 张），不横向滚动 |
| **没有滚动条组件** | `grep scrollbar src/ui` 只命中文本框内部 | 网格右缘自绘 3pt 滚动指示（长条 + 当前位置），滚动时出现，静止 1.2s 后淡出 |
| **没有拖放** | 框架没有 drag source / drop target | 不做「拖出到资源管理器」、不做「拖入文件夹」；框选用的是按下拖动，不冲突 |
| **没有全屏 API** | `Window` 只有 `close / minimize / zoom / frame / setTitle / redraw` | 不做全屏看片（列入 P2，需先在 nanoui 侧加 fullscreen） |
| **没有系统「减弱动效」探测** | 框架未暴露 | 设置里给一个「减少动效」开关，落到 config；框架补上探测后再自动跟随 |
| **没有 a11y 树** | 无平台无障碍桥 | 我们能保证的是：键盘全可达 + 焦点永远可见 + 不靠颜色表意；屏幕阅读器支持是框架缺口，明确记为限制 |
| **没有 restore-from-bin** | `ops.zig` 只有 open / reveal / trash / copy / paste / rename / exists | 删除后的 toast 只说明「已移到回收站」，**不承诺撤销** |
| **没有新建文件夹** | `ops.zig` 无 mkdir | 不做 |

## 3. 导航模型

```
根目录 (root)
└── 当前文件夹 (current)  ← 网格显示它的照片
     ├── 子文件夹 A （树里展开/折叠）
     └── 子文件夹 B
```

- **面包屑**是主路径：命令栏左侧 `根 ▸ 2024 ▸ 杭州`，每一段可点（`kit.breadcrumb`），
  点父级 = 打开那个文件夹；当前段不可点。
- **上级**：⌘↑ 或面包屑的上一段。根目录再往上是「换根」，不做（根是用户选的锚点）。
- **换根**：⌘O → 原生目录对话框（必须经 `nanoui.App.after`，见 AGENTS.md 的模态规则）。
- **树**只展开当前路径上的分支；打开一个文件夹时，它的祖先自动展开、它自己滚进视野。
- **历史**（P2）：⌥← / ⌥→ 在最近 20 个文件夹间往返；不做「前进/后退按钮」，
  因为它会跟大图的 ← → 抢语义。

## 4. 选择模型

状态里同时存在两个东西，任何时候都分开：

| | 含义 | 表现 | 谁改它 |
|---|---|---|---|
| **游标**（cursor） | 键盘现在指着哪一张 | 1px 内描边（紧贴图块）+ 悬停同样的提亮 | 方向键、单击、↑↓ 等 |
| **选择**（selection） | 动作会作用在哪些图片上 | 2px 外环 + 左上角勾 + 全选时未选中压暗 | 单击、⌘ 加选、⇧ 连选、框选、⌘A |

**规则：动作作用于「选择」，选择为空时作用于「游标」。** 这一条贯穿评分、删除、
重命名、复制、打开大图 —— 用户永远不需要先想「我到底选没选」。

| 手势 | 结果 |
|---|---|
| 单击图块 | 选择 = 仅这一张；游标 = 这一张；锚点 = 这一张 |
| ⌘/Ctrl + 单击（`c.input.adding()`） | 切换这一张在选择集合里的成员资格；游标移到它 |
| ⇧ + 单击 | 从锚点到这一张的**列表顺序**区间（不是网格行：瀑布流没有稳定行） |
| 单击空白 | 清空选择；游标不变 |
| 空白处按下拖动 >4pt | 框选：选中与选框相交的图块；⌘ + 拖动为加选；选框 = 1px `ink3` 边 + 6% `ink` 填充 |
| ⌘A | 全选当前 `shown`（筛选后的集合，不是文件夹全部） |
| Esc | 有选择 → 清空；无选择 → 关浮层 / 退出大图 |
| 双击 | 打开大图（选择保持） |
| 空格 / Enter | 打开大图（与 Finder 的快速查看同义） |

**筛选后的隐藏选中项**：搜索或星级筛选把已选中的图块藏起来时，选择**保留**，
状态条补一句「另有 3 张被筛选隐藏」，并在计数旁给出「清除筛选」的入口。
不做静默丢弃 —— 那是最容易误删的一类事故。

**选择的生命周期**：换文件夹 → 清空；重新扫描（F5 / 监视事件）→ 保留仍存在的路径；
重命名 → 选择跟着路径走；删除 → 从选择里移除。

## 5. 键盘地图

四组，互不冲突。`⌘` 在 Windows/Linux 上是 `Ctrl`（nanoui 的 `Shortcut` 已处理）。

### 全局

| 键 | 动作 |
|---|---|
| `⌘O` | 打开目录（原生对话框） |
| `⌘,` | 设置面板 |
| `⌘B` | 显示 / 隐藏导航栏 |
| `⌘F` | 聚焦搜索框 |
| `⌘D` | 外观循环：跟随系统 → 亮 → 暗 |
| `⌘↑` | 上级目录 |
| `F5` | 重新扫描当前目录 |
| `Esc` | 逐层关闭：输入框 → 浮层 → 大图 → 选择 |

### 网格（导航栏未折叠时默认焦点在网格）

| 键 | 动作 |
|---|---|
| `←` `→` | 到相邻**列**里垂直中心最近的一张 |
| `↑` `↓` | 同一列里的上一张 / 下一张 |
| `Home` `End` | 第一张 / 最后一张 |
| `PageUp` `PageDown` | 上 / 下一屏（保持列位置） |
| `Space` `Enter` | 打开游标那张的大图 |
| `0`–`5` | 给选择（或游标）打分；`0` 清除 |
| `⌫` / `Delete` | 移入回收站（1 张直接执行；多张先确认） |
| `F2` | 重命名（单张时；多张禁用） |
| `⌘C` | 复制文件到剪贴板 |
| `⌘⇧R` | 在文件夹中显示 |
| `⌘↩` | 用系统默认程序打开 |
| `T` | 打开大图并进入标签输入（标签只有一个编辑入口） |
| `⌘V` | 把剪贴板里的文件粘贴到当前文件夹 |

### 大图

| 键 | 动作 |
|---|---|
| `←` `→` | 上一张 / 下一张（现状保留） |
| `Space` `Esc` | 关闭，回到原来那张图块（游标跟着回去） |
| `0`–`5` | 打分（现状保留） |
| `T` | 标签输入（现状保留） |
| `Z` | 适应窗口 ⇄ 1:1 |
| `I` | 信息块展开 / 收起 |
| `⌫` | 移入回收站并前进到下一张（现状保留） |
| 滚轮 / 拖动 | 缩放（锚定指针）/ 平移（现状保留） |

### 导航栏（树有焦点时）

| 键 | 动作 |
|---|---|
| `↑` `↓` | 移动高亮行（折叠状态下的可见行） |
| `→` | 展开；已展开则进入第一个子项 |
| `←` | 折叠；已折叠则回到父项 |
| `Enter` | 打开（hightlight 的文件夹） |
| `Tab` | 把焦点交给网格 |

树获得焦点的路径：点击树行，或从网格按 `Tab`（焦点顺序：搜索 → 筛选 → 排序 → 树 → 网格）。
Tab 的跨控件移动依赖 `c.interact(index, .{ .focusable = true })`；P0 只保证搜索框与树的
输入可用，完整 Tab 环放在 P1（见 `05-plan.md`）。

## 6. 鼠标、滚轮、触控板

| 输入 | 网格 | 大图 |
|---|---|---|
| 滚轮 / 两指 | 垂直滚动（惯性由平台给） | 缩放（锚定指针，1.15^notch，上限 8×，现状） |
| `⌘/Ctrl` + 滚轮 | 密度档位 ±1（带 toast 提示档名） | 无 |
| 拖动 | 空白：框选；图块上：不拖动（避免与框选冲突） | 照片大于房间时平移；否则无 |
| 双击 | 打开大图 | 适应 ⇄ 1:1（现状） |
| 悬停 0.5s | 图块 ⋯ chip 与文件名条（`kit.tooltip` 延迟对齐） | 顶部条与胶片条出现（见下） |
| 指针光标 | 图块上 = 手形（`Cursor.hand`）；分隔条 = `resize_left_right` | 可拖动时 = 手形 |

**大图浮层自动隐藏**：指针静止 2.5s 后顶部条与胶片条淡出（只留信息块与缩放控件），
指针一动就回来；正在输入标签或悬停在浮层上时不隐藏。

## 7. 流程分镜

**首次打开。** 窗口按 `config` 恢复；根 = 上次根 → 命令行 → Pictures → 当前目录。
导航栏显示根与其一层子文件夹；网格先画占位骨架，状态条出现一条进度线，
窗口标题变成「正在测量 42% · NanoFlowVision」。测量够了 → 布局锁定 → 整块 120ms 淡入。
空目录 → 空态（不是空白）。

**找一张。** `⌘F` → 输入 → 每敲一个字就重排（保序，`shown_version` 机制沿用）→
计数变成「第 3 张，共 12 张」。无匹配 → 空态 + 「清除搜索」按钮 + 提示可搜文件名。
`⌘F` 之前选中的东西在筛选后仍然保留（见 §4）。

**挑拣 100 张。** 进文件夹 → 方向键走过一遍 → `1`–`5` 打分 → `⌫` 删掉不要的
（单张不打断，连续按；每删一张状态条的「已选/共」立即更新）→ 需要一次删多张时
先框选再 `⌫`，弹确认。

**整理。** 选一张 → `F2` → 输入框预填全名 → 回车 → 成功：图块文件名与状态条同步更新；
失败（重名/非法字符/占用）：toast danger + 输入框保留原值，不关闭。

**看一张。** `Space` → 大图从游标那张开始 → 顶部条「3 / 12 · 杭州-0421.jpg · ★★★☆☆」→
`I` 展开信息块 → 滚轮放大看细节 → 点胶片条第 5 张跳过去 → `Esc` 回到第 5 张的图块。

**删除。** 1 张：直接进回收站 + toast「已移到回收站 · 杭州-0421.jpg」。
多张：确认框「删除 12 张图片？」+「首张 … 末张 … 可在回收站恢复」+ 取消/删除。

## 8. 状态与文案

| 状态 | 触发 | 画面 | 文案（中 / 英） | 出口 |
|---|---|---|---|---|
| 空目录 | 文件夹里没有图片 | 居中图标 + 标题 + 说明 | 「这里没有图片」/「No pictures here」+「支持 JPG · PNG · HEIC · WebP …」 | 「打开其他目录」按钮 |
| 无匹配 | 搜索/筛选无结果 | 同上，图标换放大镜 | 「没有匹配"杭州"的图片」 | 「清除搜索」按钮 |
| 测量中 | 尚有图片未量尺寸 | 骨架墙 + 状态条进度 + 标题栏百分比 | 「正在测量 42%」 | 无（可继续滚动） |
| 解码失败 | `thumbs` 标记 failed | 图块内 `exclamationmark.triangle` + 文字 | 「无法读取」+ tooltip 原因 | 右键不可用 → ⋯ 菜单「在文件夹中显示」 |
| 目录不可读 | `scan.list` 失败 | 内容区顶部 `kit.alert`（danger） | 「无法打开这个文件夹」+ 路径 | 「选择其他目录」 |
| 选择被隐藏 | 筛选藏掉了选中项 | 状态条附加句 | 「另有 3 张被筛选隐藏」 | 「清除筛选」 |
| 写入失败 | XMP 写回失败 | toast danger | 「评分未写入文件」 | 自动消失，文件保持原样 |
| 监视暂停 | watcher 异常（P2） | 状态条黄点 | 「监视已暂停 · F5 重新扫描」 | `F5` |

所有文案进 `i18n.zig`，两种语言都要有；格式串沿用 `{d}` / `{s}` 的 `c.print` 约定。

## 9. 反馈与确认规则

- **toast**：右下角，最多 3 条堆叠，普通 4s 自动消失，危险 6s 且可手动关闭。
  只用于「刚刚发生了什么」，不用于状态（状态在状态条）。
- **状态条**：常驻事实（选中数、总数、总大小、监视、时间），不闪过。
- **确认对话框**只在两种情况下出现：一次影响 >1 个文件；或不可逆（本应用没有不可逆操作，
  回收站可恢复，所以只有「多文件」一条）。
- **不给假的确定性**：失败就说失败（重名、被占用、无权限），不静默重试。
- **动效有上限**：任何动画都不允许延迟一次点击的可见结果超过 100ms（见 03 的动效表）。

## 10. 设置项（全部落到 `config.zig` 的 `key = value`）

| 项 | 取值 | 默认 | 说明 |
|---|---|---|---|
| 外观 | 跟随系统 / 亮 / 暗 | 跟随系统 | 启动时用 `App.flags.dark`；运行中循环用 `⌘D` |
| 语言 | English / 中文 | 中文（现状） | 现状保留 |
| 包含子文件夹 | 开 / 关 | 关 | 现状保留；开时命令栏出现可关闭的 chip |
| 网格密度 | 小 / 中 / 大 | 中 | 目标行高 128 / 256 / 512（受缩略图尺寸分级约束，见 03） |
| 挑拣时压暗未选中 | 开 / 关 | 开 | 有选择时未选中图块降到 55% 不透明度 |
| 减少动效 | 开 / 关 | 关 | 关掉淡入、胶片条滑动、toast 滑入；保留必要的即时反馈 |
| 导航栏宽度 | 200–360 | 240 | 拖动分隔条改变；双击分隔条复位 |
| 记住窗口位置 | 开 / 关 | 开 | 现状保留（含最大化） |

## 11. 缺口登记（要在仓库里留痕的依赖）

1. **右键**：需要 nanoui 在 `Input` 上加 pointer button，才能有真正的上下文菜单。
2. **横向滚动**：胶片条若要做成可无限滚动，需要 `Style.scroll_x`。
3. **全屏**：`Window` 需要 fullscreen 才能「全屏看片」。
4. **a11y**：需要平台无障碍桥（macOS AX、Windows UIA），否则屏幕阅读器读不到。
5. **删除撤销**：需要 `ops.restore`（从回收站还原）才能真正给出「撤销」。
6. **系统减弱动效**：需要框架暴露偏好，设置项才能从手动变自动。
7. **拖出/拖入**：需要拖放 API；有了它，「复制到文件夹」可以变成一次拖动。

这些缺口不阻塞 P0/P1，但应在 `ROADMAP.md` 里各占一行，避免设计反复。
