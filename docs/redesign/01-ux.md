# 01 · 交互与信息架构

## 1. 三种节奏，三个表面

照片浏览器被用起来的节奏只有三种，界面必须各自给出最短路径：

| 节奏 | 用户在做的事 | 表面 | 最短路径 |
|---|---|---|---|
| **扫视**（scan） | 这一墙里有没有我要的 | 网格 | 滚轮 + 密度档 |
| **挑拣**（cull） | 这批里留下哪几张 | 网格 | 方向键 + 0–5 + ⌫ |
| **细看**（inspect） | 这一张到底怎么样 | 大图 | 空格进入，Esc 退出 |

导航栏（rail）不属于任何一种节奏，它是**换墙**的地方，所以它永远在、永远窄。

设计上的推论：**挑拣必须发生在网格里**。把 100 张照片一张张打开再关掉是最慢的路径，
所以键盘游标、选择集合、快速评分、快速删除全部长在网格上，而不是只长在大图里。

## 2. 能力边界（先说清楚不做什么，免得设计悬空）

这些是 nanoui v0.9.2 当前的边界；方案按边界设计，不按愿望设计。升级到 0.9 之后
有三条边界已经打开（右键、横向滚动、全屏），应用还没跟上，见下表「现在可以」。

| 边界 | 证据 | 设计应对 |
|---|---|---|
| **右键**：现在可以 | `Input.button` 有 left/right/middle，`Interaction.right_clicked`；Control+左键在 Windows 上也算 | 应用仍用 ⋯ chip（习惯一致），菜单已能挂到右键上；未接 |
| **横向滚动**：现在可以 | `Style.scroll_x` | 大图胶片条仍是窗口式（15 张），改成横向滚动条是新工作，未接 |
| **没有滚动条组件** | nanoui 的滚动容器自己在右缘画一条 4pt 的（`muted` 50%，常驻） | 应用不自绘滚动条；位置靠它自己说 |
| **拖放**：现在可以 | `Input.drop` / `drag_over`，`Div.acceptsDrop` | 应用未接「拖出到资源管理器」，框选用的是按下拖动，不冲突 |
| **全屏 API**：现在可以 | `Window.setFullScreen` / `isFullScreen` | 应用仍用 `src/screen.zig`（Windows `WS_POPUP` 能盖住任务栏，`setFullScreen` 只是最大化）；见 §12 |
| **没有系统「减弱动效」探测** | 框架未暴露 | 设置里给一个「减少动效」开关，落到 config |
| **a11y 树**：现在可以 | `ui.access`（macOS VoiceOver、iOS；Windows 还没有） | 应用仍靠键盘全可达 + 焦点可见；Windows 的无障碍等 nanoui 补 |
| **没有 restore-from-bin** | `ops.zig` 只有 open / reveal / trash / copy / paste / rename / exists | 删除后的 toast 只说明「已移到回收站」，**不承诺撤销** |
| **没有新建文件夹** | `ops.zig` 无 mkdir | 不做 |
| **Tab 归 nanoui 的焦点环** | v0.9 起 `Context` 自己走焦点环（rail、搜索框、网格是三个停点） | 应用不再自己吞 Tab；`rail.view` 与 `gallery.view` 把两个大盒子登记为停点 |
| **Control+左键是右键** | v0.9 把 Control+左键当 context-menu 按下 | 图块上仍把它当「加选」（`right_clicked` 且左键且 ctrl → toggle） |

## 3. 导航模型

```
根目录 (root)
└── 当前文件夹 (current)  ← 网格显示它的照片
     ├── 子文件夹 A （树里展开/折叠）
     └── 子文件夹 B
```

- **面包屑**是主路径：命令栏左侧 `根 ▸ 2024 ▸ 杭州`，每一段可点（`kit.breadcrumb`），
  点父级 = 打开那个文件夹；当前段不可点。
- **上级**：⌘↑ 或面包屑的上一段。根目录再往上是「换根」，不做（根是用户选的锚点）。
- **换根**：⌘O → 原生目录对话框（必须经 `nanoui.App.after`，见 AGENTS.md 的模态规则）。
- **树**只展开当前路径上的分支；打开一个文件夹时，它的祖先自动展开、它自己滚进视野。
- **历史**：⌥← / ⌥→ 在最近 20 个文件夹间往返；不做「前进/后退按钮」，
  因为它会跟大图的 ← → 抢语义。

## 4. 选择模型

状态里同时存在两个东西，任何时候都分开：

| | 含义 | 表现 | 谁改它 |
|---|---|---|---|
| **游标**（cursor） | 键盘现在指着哪一张 | 1px 内描边（紧贴图块）+ 悬停同样的提亮 | 方向键、单击、↑↓ 等 |
| **选择**（selection） | 动作会作用在哪些图片上 | 2px 外环 + 左上角勾 + 全选时未选中压暗 | 单击、⌘ 加选、⇧ 连选、框选、⌘A |

**规则：动作作用于「选择」，选择为空时作用于「游标」。** 这一条贯穿评分、删除、
重命名、复制、打开大图 —— 用户永远不需要先想「我到底选没选」。

| 手势 | 结果 |
|---|---|
| 单击图块 | 选择 = 仅这一张；游标 = 这一张；锚点 = 这一张 |
| ⌘/Ctrl + 单击（`c.input.adding()`） | 切换这一张在选择集合里的成员资格；游标移到它 |
| ⇧ + 单击 | 从锚点到这一张的**列表顺序**区间（不是网格行：瀑布流没有稳定行） |
| 单击空白 | 清空选择；游标不变 |
| 空白处按下拖动 >4pt | 框选：选中与选框相交的图块；⌘ + 拖动为加选；选框 = 1px `ink3` 边 + 6% `ink` 填充 |
| ⌘A | 全选当前 `shown`（筛选后的集合，不是文件夹全部） |
| Esc | 有选择 → 清空；无选择 → 关浮层 / 退出大图 |
| 双击 | 打开大图（选择保持） |
| 空格 / Enter | 打开大图（与 Finder 的快速查看同义） |

**筛选后的隐藏选中项**：搜索或星级筛选把已选中的图块藏起来时，选择**保留**，
状态条补一句「另有 3 张被筛选隐藏」，并在计数旁给出「清除筛选」的入口。
不做静默丢弃 —— 那是最容易误删的一类事故。

**选择的生命周期**：换文件夹 → 清空；重新扫描（F5 / 监视事件）→ 保留仍存在的路径；
重命名 → 选择跟着路径走；删除 → 从选择里移除。

## 5. 键盘地图

四组，互不冲突。`⌘` 在 Windows/Linux 上是 `Ctrl`（nanoui 的 `Shortcut` 已处理）。

### 全局

应用内的 `Ctrl+/` 把这张表画成两列表格（键在左、动作在右，按四组排；`i18n.keyGroups`），
中英各一份。Windows/Linux 上 Backspace 记为 `Del`（mono 字体没有 ⌫）。

| 键 | 动作 |
|---|---|
| `⌘O` | 打开目录（原生对话框） |
| `⌘,` | 设置面板 |
| `⌘B` | 显示 / 隐藏导航栏 |
| `⌘F` | 聚焦搜索框 |
| `⌘/` | 键盘一览（设置面板页脚同入口） |
| `⌘D` | 外观循环：跟随系统 → 亮 → 暗 |
| `⌘↑` | 上级目录 |
| `F5` | 重新扫描当前目录 |
| `F11` | 全屏看图（`⌃⌘F` 在 macOS 上同效） |
| `Esc` | 逐层关闭：输入框 → 浮层 → 全屏 → 大图 → 选择 |

### 网格（导航栏未折叠时默认焦点在网格）

| 键 | 动作 |
|---|---|
| `←` `→` | 到相邻**列**里垂直中心最近的一张 |
| `↑` `↓` | 同一列里的上一张 / 下一张 |
| `Home` `End` | 第一张 / 最后一张 |
| `PageUp` `PageDown` | 上 / 下一屏（保持列位置） |
| `Space` `Enter` | 打开游标那张的大图 |
| `0`–`5` | 给选择（或游标）打分；`0` 清除 |
| `⌫` / `Delete` | 移入回收站（1 张直接执行；多张先确认） |
| `F2` | 重命名（单张时；多张禁用） |
| `⌘C` | 复制文件到剪贴板 |
| `⌘⇧R` | 在文件夹中显示 |
| `⌘↩` | 用系统默认程序打开 |
| `T` | 打开大图并进入标签输入（标签只有一个编辑入口） |
| `⌘V` | 把剪贴板里的文件粘贴到当前文件夹 |

### 大图

| 键 | 动作 |
|---|---|
| `←` `→` | 上一张 / 下一张 |
| `Space` `Esc` | 关闭，回到原来那张图块（游标跟着回去） |
| `0`–`5` | 打分 |
| `T` | 标签输入 |
| `Z` | 适应窗口 ⇄ 1:1 |
| `F` | 铺满屏幕 ⇄ 1:1（画面裁边，填满整个房间） |
| `I` | 信息块展开 / 收起 |
| `⌫` | 移入回收站并前进到下一张 |
| 滚轮 / 拖动 | 缩放（锚定指针）/ 平移 |
| 按住左键 | 临时 1:1（以指针处为锚），按住期间可以拖动 |
| 按住右键 | 临时【适应窗口】，松手回到原来的大小 |

### 导航栏（树有焦点时）

| 键 | 动作 |
|---|---|
| `↑` `↓` | 移动高亮行（折叠状态下的可见行） |
| `→` | 展开；已展开则进入第一个子项 |
| `←` | 折叠；已折叠则回到父项 |
| `Enter` | 打开（高亮的文件夹） |
| `Tab` | 把焦点交给网格 |

树获得焦点的路径：点击树行，或按 `Tab` 在树与网格之间换焦点（`tree_focus`）。
搜索框、排序、密度是各自的指针/键盘控件，不在 Tab 环里。

## 6. 鼠标、滚轮、触控板

| 输入 | 网格 | 大图 |
|---|---|---|
| 滚轮 / 两指 | 垂直滚动（惯性由平台给） | 缩放（1.15^notch，上限 8×），以指针为锚 |
| 拖动 | 空白：框选；图块上：单击/加选/连选 | 照片大于房间时平移；按住左键时在 1:1 上平移 |
| 双击 | 打开大图 | 适应 ⇄ 1:1 |
| 按住 | 图块上：拖动 = 框选 | 左键 = 临时 1:1（可拖），右键 = 临时适应 |
| 悬停 | 图块立即出现 ⋯ chip 与文件名条（tooltip 另等 0.5s） | 顶部条与胶片条常驻 |
| 指针光标 | 图块上 = 手形；导航栏右缘 = `resize_left_right` | 可拖动时 = 手形 |

### 缩放的锚

滚轮缩放不是“以窗口中心缩放”：指针下的那一点必须是**画面里**的同一个点，
缩放前后都停在指针下。做法是：

- 滚轮那一刻记住指针下的画面点（`anchor`，0..1 的画面坐标）与屏幕点（`anchor_mouse`）；
- 每帧只缓动 **zoom**，`pan` 由这个锚点反解（`pan = anchor_mouse - 画面中心 - anchor × 尺寸`），
  所以缓动的每一帧、以及连续两次滚轮之间，锚点都不漂——这正是之前的 bug：
  pan 与 zoom 各自缓动、且 pan 用目标 zoom 反解，中途就错位了；
- 画面比房间小时强制居中（不留空边）；比房间大时 pan 被夹在溢出的范围内，
  所以贴边时锚点让位于“不露底”。

拖动平移时锚点跟着手走：平移量加到 pan 上，再把新的指针下画面点写回 `anchor`。

### 缩放的四个模式

`zoom_mode` 说“现在要多大”，目标值每帧算：

| 模式 | 目标 | 入口 |
|---|---|---|
| `fit` | `min(房间宽/图宽, 房间高/图高)` | 默认；`Z` 从 1:1 回来；滚轮缩到最小 |
| `fill` | `max(房间宽/图宽, 房间高/图高)` | `F`；chip 点一下（从 fit） |
| `actual` | `1.0`（1 像素 = 1 点） | `Z`；`F` 从 fill 来；chip 从 fill 点一下 |
| `free` | 滚轮给的值 | 滚轮；chip 点一下回到 fit |

`Z` 是“适应 ⇄ 1:1”，`F` 是“铺满 ⇄ 1:1”——两对各自来回，不去经第三个。
从其它模式按 `F` 先进铺满，因为那是需要说一声的那个。切模式时画面回中（anchor 清空），
滚轮再重新把锚点放到指针下。大图右下角的 chip 显示当前模式名（Fit / Fill / 百分比），
点击按 fit → fill → 1:1 → fit 循环。

`zoom_mode` 与 keys 解耦：数字键评分、`T` 标签仍只对可写（JPEG）开放；
`Z` / `F` / `I` 对所有图片都生效。

### 按住不放的临时视图

键和 chip 是“改主意”：按一下，模式就变了。手上还有一个更轻的问题——**这张到底糊不糊**，
或者**放回窗口里是什么样**——问完就不想要了。所以两个鼠标键按住时给一个临时视图，
松手原样退回：

| 按住 | 看到 | 锚 |
|---|---|---|
| 左键 | 1:1 | 指针下的那一点（和滚轮一样） |
| 右键 | 适应窗口 | 画面中心 |

规则四条：

- **两个键在任何模式都生效**，包括滚轮缩到 2.5× 这种没有名字的状态。要问的是“原尺寸
  什么样、放回窗口什么样”，这个问题和滚轮把画面留在哪儿无关。
- **左键先要“按住不动”**。左键同时是拖动的手柄，一次按下到底是“看”还是“拖”，
  要等指针动没动才知道：按下后静止 150ms（`peek_delay`）才进入查看，一动就是拖动，
  这次按下就不再变成查看。右键没有第二个用途，按下即看。
- **按住期间可以拖**。左键 1:1 时画面通常大于房间，手带着画面走是自然的；拖动移动的
  是锚点的屏幕位置（`anchor_mouse`），不是 pan——锚点反解 pan 是每帧都跑的，直接写
  pan 会被它覆盖回去，写锚点才是让“那一点”跟着手走。
- **指针位置只在按下时判一次**。1:1 的画面可能比 fit 还小（小图），它会在手下缩走；
  每帧重新判断“指针还在图上吗”会在第一帧就结束这次查看。所以 peek 一旦成立，
  就只等键松开。

退回时回的是**按下前的那一帧**，不是 fit：模式、滚轮的 zoom 目标、锚点、pan 全部
存进 `Peek` 再放回来。从 2.5× 按住左键，松手还是 2.5×，位置也一样。
临时视图不进 chip、不进 settings——它是一次提问，不是一次决定。

## 7. 流程分镜

**首次打开。** 窗口按 `config` 恢复；根 = 上次根 → 命令行 → Pictures → 当前目录。
导航栏显示根与其一层子文件夹；网格先画占位骨架，状态条出现一条进度线，
窗口标题变成「正在测量 42% · NanoFlowVision」。测量够了 → 布局锁定 → 整块 120ms 淡入。
空目录 → 空态（不是空白）。

**找一张。** `⌘F` → 输入 → 每敲一个字就重排（保序，`shown_version` 机制沿用）→
计数变成「第 3 张，共 12 张」。无匹配 → 空态 + 「清除搜索」按钮 + 提示可搜文件名。
`⌘F` 之前选中的东西在筛选后仍然保留（见 §4）。

**挑拣 100 张。** 进文件夹 → 方向键走过一遍 → `1`–`5` 打分 → `⌫` 删掉不要的
（单张不打断，连续按；每删一张状态条的「已选/共」立即更新）→ 需要一次删多张时
先框选再 `⌫`，弹确认。

**整理。** 选一张 → `F2` → 输入框预填全名 → 回车 → 成功：图块文件名与状态条同步更新；
失败（重名/非法字符/占用）：toast danger + 输入框保留原值，不关闭。

**看一张。** `Space` → 大图从游标那张开始 → 顶部条「3 / 12 · 杭州-0421.jpg · ★★★☆☆」→
`I` 展开信息块 → 滚轮放大看细节 → 点胶片条第 5 张跳过去 → `Esc` 回到第 5 张的图块。

**删除。** 1 张：直接进回收站 + toast「已移到回收站 · 杭州-0421.jpg」。
多张：确认框「删除 12 张图片？」+「首张 … 末张 … 可在回收站恢复」+ 取消/删除。

## 8. 状态与文案

| 状态 | 触发 | 画面 | 文案（中 / 英） | 出口 |
|---|---|---|---|---|
| 空目录 | 文件夹里没有图片 | 居中图标 + 标题 + 格式提示 + 两枚按钮 | 「这里没有图片」/「No pictures here」+「支持 JPG · PNG · HEIC · WebP …」 | 「打开目录」/「重新扫描」 |
| 无匹配 | 搜索/筛选无结果 | 同上，图标换放大镜 | 「没有匹配"杭州"的图片」 | 「清除搜索」按钮 |
| 测量中 | 尚有图片未量尺寸 | 骨架墙 + 状态条进度 + 标题栏百分比 | 「正在测量 42%」 | 无（可继续滚动） |
| 解码失败 | `thumbs` 标记 failed | 图块内 `exclamationmark.triangle` + 文字 | 「无法读取」 | ⋯ 菜单「在文件夹中显示」 |
| 目录不可读 | `scan.list` 失败 | 居中对话框（`kit.dialog`），页后压暗 | 「无法打开这个文件夹」+ 路径 | 「打开其他目录」 |
| 选择被隐藏 | 筛选藏掉了选中项 | 状态条附加句 | 「另有 3 张被筛选隐藏」 | 「清除筛选」 |
| 写入失败 | XMP 写回失败 | toast danger | 「评分未写入文件」 | 自动消失，文件保持原样 |

所有文案进 `i18n.zig`，两种语言都要有；格式串沿用 `{d}` / `{s}` 的 `c.print` 约定。

## 9. 反馈与确认规则

- **toast**：右下角，最多 3 条堆叠，普通 4s 自动消失，危险 6s 且可手动关闭。
  只用于「刚刚发生了什么」，不用于状态（状态在状态条）。
- **状态条**：常驻事实（选中数、总数、总大小、监视、时间），不闪过。
- **确认对话框**只在两种情况下出现：一次影响 >1 个文件；或不可逆（本应用没有不可逆操作，
  回收站可恢复，所以只有「多文件」一条）。
- **不给假的确定性**：失败就说失败（重名、被占用、无权限），不静默重试。
- **动效有上限**：任何动画都不允许延迟一次点击的可见结果超过 100ms（见 03 的动效表）。

## 10. 设置项（全部落到 `config.zig` 的 `key = value`）

| 项 | 取值 | 默认 | 说明 |
|---|---|---|---|
| 外观 | 跟随系统 / 亮 / 暗 | 跟随系统 | 启动读 `nanoui.isDark()`；运行中 `⌘D` 循环 |
| 语言 | English / 中文 | 中文 | 切换即时生效并持久化 |
| 包含子文件夹 | 开 / 关 | 关 | 开时命令栏出现可关闭的 chip |
| 网格密度 | 小 / 中 / 大 | 中 | 目标行高 128 / 256 / 512（受缩略图尺寸分级约束，见 03） |
| 挑拣时压暗未选中 | 开 / 关 | 开 | 有选择时未选中图块降到 55% 不透明度 |
| 减少动效 | 开 / 关 | 关 | 关掉 kit 的进出动画与过渡；保留选中、悬停这类即时反馈 |
| 导航栏宽度 | 200–360 | 240 | 拖动导航栏右缘改变；双击复位 |

## 11. 缺口登记（要在仓库里留痕的依赖）

1. **右键**：需要 nanoui 在 `Input` 上加 pointer button，才能有真正的上下文菜单。
2. **横向滚动**：胶片条若要做成可无限滚动，需要 `Style.scroll_x`。
3. **全屏**：nanoui 没有 API；`src/screen.zig` 自己接（见 §12）。
4. **a11y**：需要平台无障碍桥（macOS AX、Windows UIA），否则屏幕阅读器读不到。
5. **删除撤销**：需要 `ops.restore`（从回收站还原）才能真正给出「撤销」。
6. **系统减弱动效**：需要框架暴露偏好，设置项才能从手动变自动。
7. **拖出/拖入**：需要拖放 API；有了它，「复制到文件夹」可以变成一次拖动。

这些缺口记在 [ROADMAP.md](../../ROADMAP.md) 的「还没做的」与「平台债」里。

## 12. 全屏看图

一张照片占满显示器，界面让路；退出后窗口回到原样。

**入口**：`F11`；macOS 再加 `⌃⌘F`；大图顶条的 expand chip（与 info/close 并列）。
在网格里进入时先打开游标那张（没游标则第一张）的大图，空文件夹不动作。

**退出**：`F11` / `⌃⌘F` / 再点 chip / 系统手势（macOS 绿灯、触控板）。
`Esc` 的层级是：标签输入 → 菜单/浮层 → 全屏 → 大图 → 选择。全屏里按一次 `Esc`
回到窗口化的大图，再按一次才关大图。关掉大图（Esc 或 ×）也会退出全屏——
「全屏的墙」不是一种模式。

**沉浸**：进入全屏后 2.2 秒没有指针移动、按键、滚轮或点击，顶条、胶片条、缩放 chip
一起退场；任何输入立刻把它们带回来，并重新开始计时。三条规矩：

1. **不用定时器**。安静是每帧按 `c.time` 判定的（`fullscreen.noteInput`），
   没有 `App.after` 回调，也就没有「定时器早到/晚到/没装上」这一类问题；
   帧在动（比如图片还在解码）时判定照常进行。
2. **退场是渐隐，且 fit 跟着走**。`chrome_fade` 在 0.14 秒的缓动里从 1 走到 0，
   fit 的上下留白由同一个值算（`topRoom`），照片随条一起长大，不跳。
   减少动效时直接换，不做缓动。
3. **看不见的条不接点击**。`chromeLive` 在 alpha ≤ 0.35 时就不再响应；
   `chromeDrawn` 在 alpha ≤ 0.02 时连节点都不建。底下的照片照常收点击
   （点空白仍是关大图），胶片条上的滚轮也只在它还活着时才算「逐张」。

信息卡片不参与隐藏，跟着 `I` 的当前状态。顶条、胶片条、缩放 chip 三者的 alpha
是同一个值。

**窗口**：进入前记住窗口矩形（点）、样式与是否最大化；退出原样恢复。
`settings.txt` 永远写进入前的窗口，全屏的矩形绝不写进去；启动不恢复全屏。
用窗口所在显示器；Windows 覆盖显示器全 rect（含任务栏），macOS 用自己的 Space。
Linux 没有全屏 API，退化为最大化。

**实现**：`src/win.zig`（Windows 的样式/矩形）、`src/screen.zig`（平台分派 + 测试替身）、
`src/fullscreen.zig`（状态机、安静判定、渐隐、fit 的留白）、
`src/app.zig`（`fullscreen`、帧顶应用、帧前窗口保存）、
`src/large.zig`（chip、fit、顶条与胶片条的显隐与可点性）。
