## 一句话设计

> **照片是画面里唯一有颜色的东西。**
> 界面自己不着色：暗房用中性石墨、亮房用中性纸白，照片被推到最前，
> 交互的强度用**明度与形状**表达，而不是用彩色装饰。

## 设计目标（可验收）

1. **三秒定位**：任意时刻能一眼答出「我在哪个文件夹、这里有多少张、当前排序与筛选是什么」。
2. **三种节奏都有出路**：扫视（看整墙）、挑拣（选一批、打分、剔除）、细看（看一张）。
   现在只有「扫视」和「细看」，缺「挑拣」需要的选择模型。
3. **键盘全可达**：每一件能做的事都有一条键盘路径；键盘焦点永远可见。
4. **每个 >200ms 的操作都有回声**：标题栏、状态条或 toast，三处之一必须给出反馈。
5. **画面顺序永不意外改变**：滚动位置、网格排布、密度只在用户动作时改变；
   后台到达的测量结果不允许让照片在眼皮底下跳动。
6. **所有颜色都过对比度线**：正文 ≥ 4.5:1，图标与辅助信息 ≥ 3:1（数值见 03）。

## 五条原则

**一、照片优先。** chrome 的明度被限制在照片的两端之外：暗房里 chrome 不低于
`#0E0F11` 底 + `#EDEEF0` 字，亮房里不超过纸白与墨黑；chrome 不使用饱和色，
唯一的例外是内容标记（星级金）与语义色（危险红、监视绿）。

**二、一个像素一个意思。** 状态分成三个互不混淆的通道：
- **悬停**（指针在哪）：一层 4% 提亮 + 1px 细框，绝不动布局；
- **选中**（动作会作用在谁身上）：2px 环 + 角标勾 + 未选中压暗；
- **游标**（键盘在哪）：1px 内描边，紧贴图块边缘。
三者可以同时存在，任何两个叠在同一张图块上也必须可区分。

**三、表意不靠颜色。** 星级既有金色星形也有数字，选中既有颜色也有环与勾，
失败既有红色也有图标与文字。黑白截图、色盲、投影仪都要能读。

**四、即时反馈。** 移入回收站、粘贴、重命名失败、目录不可读 —— 每一种都有一条
toast 或一条状态条说明；测量进度同时出现在状态条与窗口标题栏。

**五、顺序即信息。** 网格密度是用户设定的三档之一，不是窗口宽度猜出来的；
排序的三个状态（键 / 方向 / 是否筛选）在命令栏上是常驻可见的，不藏在菜单里。

## 信息架构

应用只有三个表面，加两个浮层：

| 表面 | 在哪里 | 回答的问题 |
|---|---|---|
| **导航栏（rail）** | 左侧 240pt，可拖宽 200–360、可折叠 | 我在哪个文件夹？它下面还有什么？ |
| **网格（grid）** | 主区，命令栏 44 + 内容 + 状态条 28 | 这里有什么？我选了哪几张？ |
| **大图（lightbox）** | 全窗口，覆盖前两者 | 这一张到底拍得怎么样？ |

浮层：**⋯ 菜单 / 排序 / 密度**（`kit.menu`、`kit.popover`，层 20）、
**设置面板**（右侧 sheet）、**确认对话框**（居中 `kit.dialog`）、
**toast**（右下角 `kit.Toaster`，层 40）。各级层号与 nanoui 的
`kit.overlay.layer_popover / layer_tooltip / kit.toast.layer_toast` 一致，不自造。

## 决策记录（我替你定的默认值，都可推翻）

| # | 决定 | 理由 | 想换成什么就改哪里 |
|---|---|---|---|
| D1 | 中性色（亮 `#F7F7F4` / 暗 `#0E0F11`），放弃暖炭与奶油 | 中性灰不参与照片的色彩判断；暖底会让肤色与白平衡偏暖 | 03 的色板表，只换 hex，不动结构 |
| D2 | chrome 几乎不上色；选中 = 反相环而非彩色 | 颜色在照片上不可靠（照片本身什么颜色都有）；黑白打印也要可读 | 03「强调色策略」 |
| D3 | 网格密度 3 档（S 128 / M 256 / L 512 pt 目标行高） | 受 `thumbs.thumb_side = 256` 限制：更多档位意味着更多解码尺寸与缓存分裂 | 04「密度控件」、05 P0 |
| D4 | 设置改用右侧 sheet，不再居中弹窗 | 浏览应用里弹窗会打断「看着照片调设置」；sheet 不遮中心 | 04「设置面板」 |
| D5 | 大图胶片条是**窗口式**（当前居中的 15 张），不是可横向滚动的长条 | nanoui 的滚动容器只支持垂直（`Style.scroll` 注释），横向滚动需要自造 | 04「胶片条」 |
| D6 | 星级用金色（亮 `#8A6A10` / 暗 `#E8B93B`）而不是强调色 | 星级是内容标记，不是界面状态；它必须和选中、焦点分开 | 03 色板表 `grade` |
| D7 | 不做右键上下文菜单 | nanoui 的 `Input` 只有 `down / pressed / released / click_count`，没有 pointer button 字段 | 02「能力边界」；需要时先给 nanoui 加 API |
| D8 | 不做拖出到资源管理器、不做「撤销删除」 | `ops.zig` 只有 trash/copy/paste/rename，没有 restore、没有平台拖放 | 05 P2「依赖缺口」 |

## 与现状的差异（一屏看完）

- 侧栏底部那一摞（子文件夹 / 打开目录 / 监视 / 设置）拆开：设置去右侧 sheet，
  监视状态去状态条，子文件夹变成命令栏上的一个可关闭 chip。
- 工具条改成命令栏：面包屑常驻、标题**永远不会被挤成 0 宽**、排序键常驻可见。
- 网格加选择模型（单选 / ⌘ 加选 / ⇧ 连选 / 框选 / ⌘A / Esc）与键盘游标。
- 大图加顶部条（文件名、序号、星级）、底部胶片条、可折叠信息块。
- 菜单换成 `kit.menu`：图标 + 快捷键文案 + 分隔线 + 危险色。
- 补上空态 / 无匹配 / 测量中 / 解码失败 / 目录不可读 / 选择被筛选隐藏 六种状态。
- 所有操作有 toast 或状态条回声；测量进度写进窗口标题（`Window.setTitle`）。
- 三个主题态：跟随系统 / 亮 / 暗（`nanoui.App.flags.dark` 已在 `main.zig` 使用）。
