# NanoFlowVision 界面设计

照片是画面里唯一有颜色的东西：chrome 用中性石墨与纸白，状态用**明度与形状**表达，

## 设计目标（可验收）

1. **三秒定位**：任何时候都能一眼答出「我在哪个文件夹、有多少张、按什么排序和筛选」。
2. **三种节奏都有最短路径**：扫视（网格 + 密度）、挑拣（键盘 + 选择 + 评分/回收站）、
   细看（大图 + 胶片条 + 信息块）。
3. **键盘全可达**：每一件能做的事都有一条键；焦点永远可见（`⌘/` 一览）。
4. **每个 >200ms 的操作都有回声**：toast、状态条或标题栏，三处之一。
5. **画面顺序永不意外改变**：滚动位置、排布、密度只在用户动作时改变。
6. **颜色全部过对比度线**：正文 ≥ 4.5:1，图标与辅助信息 ≥ 3:1。

## 五条原则

1. **照片优先**：chrome 的明度限制在照片两端之外；唯一的内容色是星标金，
   语义色只有危险红与监视绿。
2. **一个像素一个意思**：悬停（提亮 + 细框）、选中（反相环 + 勾 + 压暗其他）、
   游标（内描边）三个通道分开，任意两个叠在同一块上也必须可辨。
3. **表意不靠颜色**：星级既有颜色也有星形，选中既有颜色也有环与勾。
4. **即时反馈**：删除、粘贴、重命名失败、目录不可读、测量进度，各有去处。
5. **顺序即信息**：排序键与方向常驻状态条；密度是用户设定的三档，不由窗口宽度猜。

## 信息架构

| 表面 | 在哪里 | 回答的问题 |
|---|---|---|
| **导航栏** | 左 240pt（可拖 200–360，⌘B 折叠） | 我在哪个文件夹？下面还有什么？ |
| **网格** | 主区：命令栏 44 + 内容 + 状态条 27 | 这里有什么？我选了哪几张？ |
| **大图** | 全窗口 | 这一张到底怎么样？ |

浮层：菜单 / 排序 / 密度（`kit.menu`）、设置 sheet、确认框（`kit.dialog`）、
toast（`kit.Toaster`）。层号沿用 kit，不自造。

## 仍然有效的决定（都可推翻，改对应规格即可）

| # | 决定 | 理由 |
|---|---|---|
| D1 | 中性色（亮 `#F7F7F4` / 暗 `#0E0F11`），不用暖炭与奶油 | 暖底会参与照片的肤色与白平衡判断 |
| D2 | chrome 不上色；选中 = 反相环 | 颜色在照片上不可靠；黑白截图也要可读 |
| D3 | 网格密度三档（128 / 256 / 512 目标行高） | 缩略图缓存按解码边长分级，档位多了命中率掉 |
| D4 | 设置用右侧 sheet，不用居中弹窗 | 调设置时不想被遮住照片 |
| D5 | 大图胶片条是窗口式（最多 15 张），不横向滚动 | nanoui 的滚动容器只有垂直方向 |
| D6 | 星级用金色 | 星级是内容标记，必须与选中、焦点分开 |
| D7 | 不做右键菜单 | nanoui 的 `Input` 没有按键位；⋯ 角标 + 快捷键是替代 |
| D8 | 不做拖出到资源管理器、不做撤销删除 | `ops.zig` 没有拖放与 restore；删除只承诺「已移到回收站」 |

## 能力边界（nanoui 0.6.4）

没有右键、横向滚动、滚动条组件、拖放、全屏 API、系统「减弱动效」探测、a11y 树。
界面按这些边界设计：⋯ 角标替代右键，窗口式胶片条替代横向滚动，设置里的开关替代系统探测，
键盘全可达 + 焦点可见替代 a11y 桥；全屏与拖放记在 [../../ROADMAP.md](../../ROADMAP.md)。
