## 任务背景
工作区 `NanoFlowVision`（位于 tiramission 下）→ 用 **nanoui** 框架重写 **FlowVision**。
用户确认的方向：**纯 Zig 原生 UI** / **v1 最小可用闭环**（目录树 + 瀑布流缩略图 + 双击大图 + 后台解码缓存）/ **Windows 优先**。

## FlowVision 调研（netdcy/FlowVision，只读参考）
- macOS Swift/AppKit 瀑布流图片浏览器 v1.7.6，GPL-3.0，macOS 11+。
- 51 个 Swift 文件 / 32,944 行。依赖 ffmpeg-kit、BTree、Settings、SDWebImageWebPCoder。构建需 Xcode 15.2+。
- 4 种布局 justified/waterfall/grid/detail；`recalcLayout` 用 `layoutCalcPos` 增量算缩略图尺寸。
- 性能手段：LargeImageProcessor 缓存、TaskPool 优先级队列、目录监听。

## nanoui 调研（justrach/nanoui，tag v0.6.4，commit f34d980）
- Zig 0.17 跨平台 UI 框架，MIT。两种窗口模式：Native UI（自绘）/ WebView 页（仅 macOS）。
- 渲染：macOS/iOS=Metal+CoreText；Linux=GTK3+OpenGL3.3 或 CPU raster；Windows=Win32+CPU raster+自研 TrueType。
- 关键 API：`ui.div(c).row().gap(8)`、`ui.list`（**仅等高行** uniform_list）、`ui.image`（2048² BGRA 图集，max_side **1024**）、
  `ui.texture`（外部 GPU 纹理，**可绕开图集限制**）、`ui.Texture{width,height,bgra,stride}`（BGRA **预乘**）、`ui.Shortcut.escape`。
- `Context`：`c.theme`、`c.print`、`c.peekId(null)`（取下一个节点的 id）、`c.rects`（**跨帧保留**，`c.begin()` 不清）、
  `c.scroll.get(id)`（上一帧滚动偏移）、`c.node(i).rect`（**只在 arrange 后才有值**，view 期间读不到）。
- 绝对定位：`.absolute()` 放在父内容原点 + `.offset(x,y)`，随父滚动；`fixed` 则相对窗口。
- 线程唤醒：`App.onMain(ctx, fn)`（**任意线程可调**，Windows 走 fdwatch）；`Window.redraw()` 必须主线程。
- 平台差异：Windows 上 `App.onMain` 在 `windows/app.zig`；非 macOS **只有 PNG 解码器**（`png_decode.zig`），macOS 才有 ImageIO。
- 规约：每文件 ≤600 行、Zig 0.17 API、开发时不弹窗（用 `--nanoui-snapshot` / `ui.Tester`）。

## 关键技术决策
1. **绕开 nanoui 图集，用 `ui.texture` 直接传 BGRA 像素**。
   理由：`ui.image` 的图集最长边 1024 → 大图看不了；图集满了清空重排 → 滚动卡顿。
2. **布局解析化**：只读文件头（PNG/GIF/BMP/JPEG SOF）拿宽高比，零像素解码即可算出瀑布流布局，
   任意照片的位置都能直接算 → 视口外一个都不构建（自建变高虚拟化，`ui.list` 做不到）。
3. **图片解码用 zigimg**（zigimg/zigimg，纯 Zig，同样要求 Zig 0.17.0），支持 JPEG/PNG/BMP/GIF/TIFF 等。

## Zig 0.17 API 坑（本项目踩过）
- `std.Thread.Mutex` / `Condition` 已移到 `std.Io`：`std.Io.Mutex.lockUncancelable(io)` / `.unlock(io)`、
  `std.Io.Condition.waitUncancelable(io, &mutex)` / `.signal(io)` / `.broadcast(io)`。
- `std.Thread.sleep` 不存在 → `std.Io.sleep(io, .fromMilliseconds(5), .awake)`（Clock 枚举是 real/awake/boot）。
- `std.process.Args.iterate` 在 Windows 不可用 → 用 `std.process.Args.iterateAllocator(args, gpa)`（要 deinit）。
- `std.mem.readInt(T, *const [N]u8, endian)` 仍存在，但要求**定长数组指针**（切片长度须编译期已知）。
- `std.StringHashMap` **不复制 key**，且没有 `.empty` 默认值 → 改用 `StringHashMapUnmanaged` 并自己持有 key。
- `std.Io.Dir.openFileAbsolute` 断言路径必须是绝对路径 → 缓存 key 与文件路径必须分开。
- `std.Io.Dir.readFileAlloc` 只支持相对路径；绝对路径用 `openFileAbsolute` + `file.reader(io, buf).interface.allocRemaining(gpa, limit)`。

## 踩过的真实 bug（已修）
1. **预乘公式少了平均因子**：`acc[b] * a / 255` 应为 `sum(b*a) / (n*255)` → 否则 >255 触发 @intCast panic。
2. **大图缓存 key 当成文件路径用**："L:<path>" 前缀让 `openFileAbsolute` 的绝对路径断言失败 → worker 线程崩溃。
   现在 Job 同时带 `path`（文件）与 `key`（缓存键）。
3. `Pool.stop()` 漏释放 threads 数组 → 测试的 leak 检测报错。
4. 瀑布流列数用了硬编码 200px 目标宽度 → 改成 `Options.target` 显式参数。

## 阶段 1 完成（把浏览做扎实）
- **布局稳定**：宽高比改为**先全部量完再布局**（只读文件头），量完前显示 "measuring N of M…"，
  量完后布局只做一次，只有窗口宽度变了才重排 → 画廊不再跳动、滚动不漂。
  代价：打开文件夹有一次短暂等待。
- **方向预取**：往前 2 屏、往后 0.5 屏，方向随滚动方向反转。
- **LRU 淘汰**：改为按最近使用淘汰（`get` 时 touch），可见的受保护。
- 顺带修：缓存按文件夹走（`clear()` + 世代号，迟到结果丢弃）；淘汰挪到建纹理之前（原来会用到已释放像素）；
  任务队列改 O(1) 出队（原来 `orderedRemove(0)` 一次排几千个任务会 O(n²)）。
- 结果：17 个测试全绿；200 张目录峰值内存 83 → 108 MB（多解了一屏半的预取缩略图）。
- 24 MP 照片仍是 450 MB —— 那是阶段 3（解码路径）的问题，阶段 1 动不了。

## 新学到的 nanoui / Zig 0.17 细节
- `c.scroll.put(c.gpa, id, offset)` **可以写**滚动偏移（list.zig 就是这么用的）→ 可用来复位到顶部。
- `c.rects` **跨帧保留**（`c.begin()` 不清它），所以 view 里能读到上一帧的盒子位置；
  但 `c.node(i).rect` 只在 `arrange` 之后才有值，view 期间读到的永远是当前帧的 0。
- `ui.Shortcut.escape` 是 `u21` 常量，`.key = .escape` 会被当成枚举字面量报错，要写 `ui.Shortcut.escape`。
- `ui.Tester.scroll(x, y, dy)`：**负 dy 才是往下滚**（`applyScroll` 里是 `offset - dy`）。
  nanoui 自己的测试也是 `t.scroll(100, 100, -50)`。
- `std.Io.Clock` 的成员是 `real` / `awake` / `boot`，没有 `monotonic`。
- `std.Io.Mutex` / `Condition` 都在 `std.Io` 里，且方法都要传 `io`：`lockUncancelable(io)`、
  `unlock(io)`、`cond.waitUncancelable(io, &mutex)`、`cond.signal(io)`、`cond.broadcast(io)`。
- `std.StringHashMap` 不复制 key、也没有 `.empty` 默认值 → 用 `StringHashMapUnmanaged` 自己持有 key
  （插入时 dupe，删除/清空时 free）。
